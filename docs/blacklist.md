# QQ 用户和群黑名单（实验性）

该功能针对 SnowLuma 接入的 QQ 账号和 QQ 群，默认名单为空。命中用户或群时，大肥鱼在 OpenClaw 的常规消息分发前静默拦截，大肥鱼自己的 `/fish` 指令也再次检查。**此功能尚未在实际 QQ 环境完成端到端验证。**

## 1. 配置管理员

先配置[管理员 QQ 号](permissions.md)，同时确保该管理员被 SnowLuma/OpenClaw 允许发送命令。只有已授权的管理员能更改名单。

## 2. 在 QQ 管理

以下示例中的号码需换成实际 QQ 号或群号：

```text
/fish blacklist add user 123456789
/fish blacklist remove user 123456789
/fish blacklist add group 987654321
/fish blacklist remove group 987654321
/fish blacklist list
```

`user` 是发消息的 QQ 用户；命中时该用户在私聊和任何群里的请求都会被拦截。`group` 是群号；命中时该群中各用户的请求都会被拦截。身份无法验证、且有关名单非空时会保守拦截。名单查询在管理员私聊中显示每类前 20 项，在群里只显示数量。

黑名单优先于管理员权限：如果拉黑管理员本人，或管理员在被拉黑的群发送指令，也不会获得回复。请通过未被拉黑的管理员私聊解除；若所有管理员都被拉黑，在停止 Gateway 后由服务器管理员修改状态文件恢复。

## 3. 用配置文件设置初始名单（可选）

将以下内容合并到 OpenClaw 已有配置中：

```json
{
  "plugins": {
    "entries": {
      "fatfish": {
        "config": {
          "blacklist": {
            "users": ["123456789"],
            "groups": ["987654321"]
          }
        }
      }
    }
  }
}
```

号码以字符串填写，每类最多 1000 个。初始配置只在不存在已保存名单时使用。首次通过 QQ 改动后，完整名单保存在 OpenClaw 状态目录的 `fatfish/blacklist.json` 并优先于初始配置；重启后保留。需要重新使用配置文件中的初始名单时，停止 Gateway，备份并删除该状态文件，再启动 Gateway。不要直接删除包含其他数据的目录。

## 适用范围

- 拦截依赖 OpenClaw 正常加载大肥鱼并运行 `before_dispatch` 钩子；可用 `openclaw plugins inspect fatfish --runtime --json` 检查是否加载。不同 OpenClaw、SnowLuma 和原生命令路径可能存在差异，实际使用前必须分别测试用户私聊、群聊、@ 和命令。
- SnowLuma 在交给大肥鱼之前可能已经接收、聚合或缓存消息。此黑名单不是聊天记录删除功能，也不能保证黑名单用户的历史消息不会出现在其他人的上下文或群摘要中。如需不收集这些消息，应在 QQ 通道入口实现过滤，并在完成验证前关闭群摘要等聚合功能。
- 已经开始的任务、计划任务、其他插件直接发送和绕过该钩子的通道路径不由本功能保证拦截。需要完全禁止群内主动发送时，应同时使用通道自身的访问控制。
- 名单损坏或读取失败时，该钩子会静默阻止它收到的 SnowLuma 消息；插件未加载时钩子不会执行，因此不能将其当作独立的安全边界。按管理员权限保护状态目录。
