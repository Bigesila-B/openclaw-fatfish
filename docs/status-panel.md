# QQ 机器人状态面板设计（尚未实现）

## 目的与指令

使用单一指令 `/fish status` 查询大肥鱼状态，默认只允许主人私聊查询完整报告；`/fish` 和 `/fish help` 已作为指令列表入口。指令别名、群内简报及授权均由管理员配置，禁止抢占 OpenClaw 自带 `/status`。需先在目标 QQ 通道实测斜杠命令和 @ 场景的路由行为。

默认渲染 PNG 状态卡片，频道不支持图片或渲染失败时发送同权限的纯文本。示例值均为演示，不代表当前机器人状态。命令不进入大模型推理；成功调用不产生额外聊天模型 token，但收集用量不得触发额外付费模型调用。若上游数据无法读取，该字段明确显示“不可用”，不填零或虚构数据。

## 字段与数据来源

| 区域 | 数据 | 获取策略 / 注意点 |
|---|---|---|
| 连接 | SnowLuma、QQ、Gateway 状态 | 分别读取可信状态；无法确定显示未知，不应凭进程存在就说 QQ 在线。 |
| 模型 | 当前会话实际供应商 / 模型 ID | 从 OpenClaw 当前会话读取，显示实际值而非仅显示默认配置；不可用时标记。 |
| 上下文 | 当前会话已使用 / 窗口上限、百分比 | 使用 OpenClaw 当前上下文快照，不等同于累计 token。分母不明则不计算百分比。 |
| 用量 | 今日、本自然月输入/输出 token | 使用 OpenClaw 有权限的用量汇总；明确统计范围（本机器人或指定 Agent、涉及哪些会话）、起止时间、时区、是否完整。不等同于供应商账户账单。 |
| 主机 | CPU 使用率、内存、磁盘 | CPU 使用两个时间点采样；内存明确显示使用量及总量；磁盘显示所监控挂载点和已用/总量。标注宿主机或容器范围。 |
| 显卡 | 设备名称、GPU 负载和显存 | NVIDIA 可按环境尝试只读采集；AMD、Intel、容器无权限等情况可能不支持，显示不可用。多卡分开显示。 |
| 功能 | TTS、STT、生图、生视频 | 分别区分未实现、未安装、已关闭、未配置、已配置未测试、最近测试成功/失败；需标注最近检测时间。读取状态时不自动运行生成、消耗额度或调用付费 API。 |
| 任务 | 排队中、进行中、最近失败数 | 仅当任务系统实现后显示；不能将未实现当作零任务。 |

可选显示上次消息时间、运行时长、版本、队列、限额和最近错误摘要。不得显示密钥、完整 API 地址、聊天内容、IP 或其他群的会话详情。带费用信息须注明币种、来源、估算和不完整情况，不应误称账单。

参考：[OpenClaw token 与用量](https://docs.openclaw.ai/reference/token-use)、[会话用量 RPC](https://docs.openclaw.ai/gateway/opentelemetry/spans-and-events)。用量 API 需要相应权限；优先使用受支持的本地接口，不扩大令牌权限或把凭据暴露给 Agent。

## 权限与泄露边界

- 完整卡片默认只允许 OpenClaw 能可靠识别的主人在私聊请求；不能仅凭模型输出、消息中的 QQ 号或群聊文本判断身份。
- 群内可选简报只包含管理员明示公开的非敏感信息。即使主人在群里请求，也不能自动发出含私密信息的完整面板；提示私聊查询。
- 未识别身份默认拒绝；权限、时区、开关仅由受信任的本地管理入口更改，不通过普通聊天文本直接修改配置。
- 同一用户和会话设置查询冷却，主机数据采样与用量查询采用短期缓存。查询过程不得自动运行昂贵的健康测试。
- 临时图片必须做好访问限制和过期清理；图片和文本采用同一授权过滤，防止图片失败时降级文本泄露。

## 配置建议

1. 指令与权限：主指令、别名、主人私聊、群内公开字段、冷却时间。
2. 显示内容：各模块开关、时区、统计范围、本自然月 / 近 30 天、单位、图片或文字、主题。
3. 主机监控：CPU 采样周期、监控磁盘路径、容器 / 宿主机范围、GPU 采集开关。
4. 功能健康检查：手动测试、结果有效期和超时；不把“已配置”写成“可正常使用”。
5. 资源告警：阈值和持续时间，默认关闭，独立于按需查询；只有明确配置接收人后才通知。

## 开发与验收

先确认目标 QQ 通道的命令传递及结构化图片发送，再分别实现状态采集、权限过滤、渲染和发送。为每个数据源记录成功/未知/不完整并允许局部失败。测试会话与群隔离、权限拒绝、时区月初、容器限制、无 GPU、空数据、消息发送失败和文字降级；最后在真实 SnowLuma 环境进行私聊和群聊端到端验证。
