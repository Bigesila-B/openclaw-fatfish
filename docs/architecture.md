# 架构和路线

## 目标

SnowLuma / QQ 通道负责收发；OpenClaw 负责会话和工具调用；大肥鱼负责可选能力与配置体验。每种媒体能力单独开启，优先提供本地或无需付费 API 的方案，并解释硬件、网络、模型许可和服务限制。

## 当前实现

本仓库有实验性 Edge TTS、管理员授权、本机 ComfyUI 生图和视频工具。它不提供 QQ 通道、消息决策器、可视化面板、STT、持久任务队列或长期记忆。媒体功能和管理员权限尚未完成真实 QQ 环境端到端验证。

## 后续设计

1. 在真实 OpenClaw / SnowLuma 环境验证插件加载、QQ 私聊和群聊，以及不同音频格式能否发送。
2. 验证通道能否观察未 @ 的群消息。将去重、权限、群聊上下文、发言决策和发送职责清晰落在单一消息链路，避免重复回复。
3. 参考 MaiBot 的消息合并、观察上下文、自主决定是否发言和按群频率控制；群与私聊的记录及权限隔离。明确请求和管理指令不应被闲聊频率误拦。
4. 添加配置向导和功能级开关，密钥不写入仓库。各供应商应有连通性测试、错误说明和中文配置教程。
5. 候选 STT 为本地 faster-whisper；生图、生视频可探索本地 ComfyUI。选型需实测安装、许可证、模型及硬件要求后再标记支持。
6. 长任务保存创建、运行、生成完成与发送状态；重试发送不能重复生成或扣费。
7. 提供按权限显示的 QQ 状态卡片，设计见 [状态面板](status-panel.md)；目前尚未实现。

## 边界

本项目不会把同一 QQ 事件交给多个自动回复系统独立处理。只观察经用户授权的聊天；不开启群聊观察时，不应持久化其内容。第三方服务的可用性、免费额度及条款会变化，教程应以服务商当前说明为准。
