# 架构和路线

## 目标

QQ 通道负责收发（官方 QQBot 或 SnowLuma OneBot）；OpenClaw 负责会话和工具调用；大肥鱼负责可选能力与配置体验。每种媒体能力单独开启，优先提供本地或无需付费 API 的方案，并解释硬件、网络、模型许可和服务限制。

## 通道适配层

两种 QQ 接入方式的差异被收拢在 `src/identity.js` 一个模块里，其余代码只认「可信通道 + 合法用户标识」这两个结论：

| 关注点 | SnowLuma（OneBot） | 官方 QQBot |
|---|---|---|
| 通道 ID | `snowluma` | `qqbot` |
| 用户标识 | QQ 号（5-15 位数字） | openid（字母数字，通常 32 位） |
| 会话标识 | `group:<群号>` / `private:<QQ>` | `group:<group_openid>` / `c2c:<openid>` / `channel:<频道ID>` |

`parseConversation` 同时接受带通道前缀（`qqbot:group:X`）和不带前缀（`group:X`）两种写法，因为 OpenClaw 在部分调用点会剥掉前缀，另一些调用点不会。

可信通道由 `platform.channels` 配置，默认 `["snowluma", "qqbot"]`。**通道不可信或标识格式不匹配时一律按身份不可验证处理（fail-closed）**，不给功能授权，也不做黑名单放行判断。新增第三种通道只需要在 `identity.js` 里加一条标识规则。

## 当前实现

本仓库提供可选媒体供应商、人格、黑名单、权限、表情包、视频理解、链接解析，并新增状态卡片、持久生成任务、标准附件处理与轻量群聊策略。它不提供独立 QQ 协议实现、长期记忆或多节点调度。实际 QQ 多媒体与群聊行为仍需真实环境验证。

> 所有工具都以可选工具（`optional: true`）注册，**必须由用户写入 `tools.alsoAllow` 才对模型可见**。这是 OpenClaw 的既定行为，不是本插件的权限设计。缺少这一步时 `/fish` 指令仍可用，但 AI 不会主动调用任何大肥鱼能力。

## 模块边界

- `src/index.js` 负责向 OpenClaw 注册工具、命令和钩子；生成工具在调用供应商前后检查 QQ 用户权限。
- `src/identity.js` 集中定义通道 ID、用户标识格式和会话解析；新增接入方式只改这里。
- `src/providers/index.js` 是管理员配置选用供应商的注册表；`agnes.js`、`mimo.js`、`siliconflow.js` 各自实现对应服务的协议，`shared.js` 放公共的凭据读取、响应处理和文件保存。已有本地能力保留在 `comfy.js` 和 `tts.js`。
- 新增图片、视频或 TTS 供应商时，增加独立适配器，在注册表中登记，再扩展配置 schema、教程和针对真实协议的测试。供应商由管理员配置选择，聊天模型不能直接选择密钥或任意服务地址。
- 新增不属于现有媒体类型的功能，应独立实现模块，并在 `src/index.js` 显式注册和校验权限；按需增加配置开关和教程。这是代码级模块化，当前不是可热安装的第三方模块市场。
- 看视频功能由 `src/video-watch.js`、`python/video_context_helper.py` 以及从 GitHub 安装的 Video Context Builder 构成；技能入口位于 `skills/fatfish-watch-video`，默认关闭且使用独立的 QQ 用户权限。
- 可选功能默认关闭；聊天模型由 OpenClaw 管理，硅基流动 STT 通过 OpenClaw 媒体理解供应商接口注册。密钥在 Gateway 环境变量中提供。
- `src/capabilities.js` 集中维护媒体功能名称、权限和教程。`context.js` 归一化账号、用户、会话及线程，避免跨用户或跨机器人发送。
- `src/status/` 分离只读用量观测、主机采集、数据过滤、图片/文字布局及发送；采集器支持独立失败降级与受信代码扩展，随包字体和 WASM 减少系统依赖。
- `src/tasks.js` 保存图片/视频任务，后台并行有上限，服务端编号收到即落盘；Agnes 视频重启只恢复 GET。`media-delivery.js` 独立保存发送回执，避免发送重试触发生成。
- `src/attachments.js` 只接受宿主标准附件事实，创建用户绑定的短期编号；`media-codec.js` 有界转码，模型不能输入本地路径。`chat-strategy.js` 默认关闭，只在管理员指定群做内存短期观察和发言频率控制。
- `src/state-store.js` 提供小规模 JSON 原子替换和进程内共享写队列；不用于多个 Gateway 并行写同一目录。

## 仍需实际环境验证

1. 在真实 OpenClaw 环境验证插件加载、QQ 私聊和群聊，以及不同音频格式能否发送；官方 QQBot 通道还需要一轮完整端到端验证。
2. 验证通道能否观察未 @ 的群消息。将去重、权限、群聊上下文、发言决策和发送职责清晰落在单一消息链路，避免重复回复。
3. 对照真实通道确认标准附件事实、QQ SILK 解码与媒体回执语义；旧通道缺少事实时需要上游适配，不猜测协议字段。
4. 验证生成任务恢复、图片卡片在两种 QQ 通道上的实际效果；供应商实时价格和额度以官方为准。

扩展配置时同时补充 manifest schema、功能注册表、权限判断、教程及协议测试。面板新采集器、供应商和聊天策略互相独立；当前是代码级模块化，并非任意第三方模块热加载市场。

## 边界

本项目不会把同一 QQ 事件交给多个自动回复系统独立处理。只观察经用户授权的聊天；不开启群聊观察时，不应持久化其内容。第三方服务的可用性、免费额度及条款会变化，教程应以服务商当前说明为准。
