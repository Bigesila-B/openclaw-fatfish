# 架构和路线

## 目标

SnowLuma / QQ 通道负责收发；OpenClaw 负责会话和工具调用；大肥鱼负责可选能力与配置体验。每种媒体能力单独开启，优先提供本地或无需付费 API 的方案，并解释硬件、网络、模型许可和服务限制。

## 当前实现

本仓库有实验性 Edge / MiMo TTS、MiMo 音色克隆、硅基流动 STT 供应商、Agnes 和本机 ComfyUI 生图与视频工具，以及管理员授权、QQ 黑名单和聊天人格。QQ 语音输入链路尚未补齐或验证。它不提供 QQ 通道、消息决策器、可视化面板、持久任务队列或长期记忆。媒体、黑名单、人格和管理员权限尚未完成真实 QQ 环境端到端验证。

## 模块边界

- `src/index.js` 负责向 OpenClaw 注册工具、命令和钩子；生成工具在调用供应商前后检查 QQ 用户权限。
- `src/providers/index.js` 是管理员配置选用供应商的注册表；`agnes.js`、`mimo.js`、`siliconflow.js` 各自实现对应服务的协议，`shared.js` 放公共的凭据读取、响应处理和文件保存。已有本地能力保留在 `comfy.js` 和 `tts.js`。
- 新增图片、视频或 TTS 供应商时，增加独立适配器，在注册表中登记，再扩展配置 schema、教程和针对真实协议的测试。供应商由管理员配置选择，聊天模型不能直接选择密钥或任意服务地址。
- 新增不属于现有媒体类型的功能，应独立实现模块，并在 `src/index.js` 显式注册和校验权限；按需增加配置开关和教程。这是代码级模块化，当前不是可热安装的第三方模块市场。
- 可选功能默认关闭；聊天模型由 OpenClaw 管理，硅基流动 STT 通过 OpenClaw 媒体理解供应商接口注册。密钥在 Gateway 环境变量中提供。

## 后续设计

1. 在真实 OpenClaw / SnowLuma 环境验证插件加载、QQ 私聊和群聊，以及不同音频格式能否发送。
2. 验证通道能否观察未 @ 的群消息。将去重、权限、群聊上下文、发言决策和发送职责清晰落在单一消息链路，避免重复回复。
3. 参考 MaiBot 的消息合并、观察上下文、自主决定是否发言和按群频率控制；群与私聊的记录及权限隔离。明确请求和管理指令不应被闲聊频率误拦。
4. 添加配置向导和功能级开关，密钥不写入仓库。各供应商应有连通性测试、错误说明和中文配置教程。
5. 补齐并验证 SnowLuma 收到的 QQ 语音到 OpenClaw 音频附件的链路；本地 STT 可继续探索 faster-whisper。
6. 长任务保存创建、运行、生成完成与发送状态；重试发送不能重复生成或扣费。
7. 提供按权限显示的 QQ 状态卡片，设计见 [状态面板](status-panel.md)；目前尚未实现。

## 边界

本项目不会把同一 QQ 事件交给多个自动回复系统独立处理。只观察经用户授权的聊天；不开启群聊观察时，不应持久化其内容。第三方服务的可用性、免费额度及条款会变化，教程应以服务商当前说明为准。
